# X & Reddit 社区热议 · 写稿规范

你要把 `x_report.py --mode fetch` 输出的素材写成一份中文播报，存到 `logs/report_draft.txt`，
再由 `x_report.py --mode send` 推送飞书并同步归档至 Notion。

## 这份播报解决什么问题

用户每天要知道 **X 与 Reddit 上 AI 圈真正在吵什么、一线开发者实测翻车在哪**，而且要能**一键跳到原帖现场自己看**。
媒体转述会丢掉分歧双方的原话，所以这份稿子的价值不在"我告诉你发生了什么"，
而在"我把现场指给你看"。

**它是深度层，不是广度层。** AINews 的 Twitter Recap 每天聚焦最核心的一两场大争论，Reddit Recap 则聚合了 12 个核心 AI subreddit（以 `r/LocalLLaMA`、`r/localLLM`、`r/singularity`、`r/OpenAI`、`r/ClaudeAI`、`r/GeminiAI` 等为主）的一线真机实测、量化反馈与社区吐槽。
「今天 AI 圈有哪些客观大事」由同一个机器人先发的《AI 产业日报》负责，不要为了显得全面而硬凑话题数，更不要把产业日报里的通稿搬过来充数。

**⚠️ 严控噪音与前序去重（09:00 三合一流水线第 2 棒铁律）：**
1. **完整读取 Latent Space `[AINews]` + 强力去噪筛优**：`fetch` 已将完整 `AI Twitter Recap` 与 `AI Reddit Recap` 拉入 `last_context.txt`。写稿时必须先通读完整提纲与正文：
   - **X 主体板块（1–4 条）**：按讨论中心度（被引用次数多、引发真正正反技术争论或实测打脸）严格筛选最高优先级的 1–4 个焦点议题，果断砍掉只有 1 次顺带提及的边角料、招聘/活动宣发、客套吹水与次优先级噪音。
   - **Reddit 实测与吐槽板块（1–2 条，置于文末 `📎 主流媒体同期在报` 之前）**：专挑 **X 主体板块未展开（或带出截然不同的一线真机实测/量化翻车/工具踩坑视角）** 的 1–2 个高活跃度议题。如果当天 Reddit 讨论与 X 主体完全重复且没有新增实测结论、或素材不含 `Reddit Recap`，则**整块省略，绝不硬凑**。
2. **承接第 1 棒《AI 产业日报》去重**：若 `TODAY_LEDGER` 显示某事件已在当早《AI 产业日报》播过客观事实：
   - 若该事件在 X / Reddit 上并无实质技术分歧（只是单向转发官宣），**本篇直接跳过**；
   - 若该事件引发了激烈交锋或第三方实测质疑，**直接切入正反方争论与实测数据**，绝不重复交代《AI 产业日报》已写过的背景通稿。
3. **为第 3 棒《AI Builder 日报》让路**：若某条只是单人技术长文/个人开源项目分享、不存在社区多方争论（即没有 `Supportive vs Critical` 碰撞），留给紧接着跑的第 3 棒《AI Builder 日报》深写，本篇专注「多方吵架、一线实测与技术分歧」。

## 硬性要求（违反就等于白写）

1. **正文中点名必挂行内超链接，文末保留 1 条主原帖直链：**
   - **X 板块行内直链**：凡是在正文讨论中明确提到的具体人物、`@handle`、独立评测机构、研究实验室或官方账号（如 `Artificial Analysis`、`Google DeepMind`、`@skalskip92`、`@simonw`、`@theo` 等），**只要素材（`Twitter Recap 正文` 的 `[文字](URL)` 或 `原帖排行`）中给出了对应原帖/来源链接，就必须在正文中首次点名处直接为该人名、`@handle` 或机构名加上 `<a href="URL">...</a>` 超链接**，方便读者点击跳转核对原帖！**严禁只写裸文本 `@handle` 或机构名而不加链接（除非素材里确实没有任何对应链接）**。
   - **X 板块文末主原帖**：每条 X 话题末尾**仍只选被引用次数最多的那 1 条 `x.com/<user>/status/<id>` 原帖直链**贴在 `原帖：` 行（保持文末排版清爽，不堆砌长串链接）。`send` 模式会检查，全篇一条 X 原帖都没有直接拒发。
   - **Reddit 板块原帖直链**：每条 Reddit 话题标题必须以 `<b>[r/{Subreddit}] {话题标题}</b>` 开头（如 `<b>[r/LocalLLaMA] ...</b>`），末尾 `原帖：` 行贴上素材中对应的 `https://www.reddit.com/r/.../comments/...` 直链，并按素材标注照实写明 `（AINews 活跃度 {N}）`（如素材未标活跃度则省略括号，绝不编造）。若正文引用了同节内另一条不同 Reddit 帖或 Hugging Face / 博客外链，可随文挂 `<a href="URL">`。
2. **所有链接必须真实来自素材（`原帖排行`、`Twitter Recap 正文`、`Reddit 原帖排行` 或 `Reddit Recap 正文` 里的 `[锚文本](URL)`），绝对禁止自己编造或拼接 URL / status id。** 没有提供确切链接的人物/观点就老实写纯文本，宁缺毋滥。
3. **口径必须严格诚实：**
   - X 板块不要把"被引用次数"写成"点赞数"或"最高赞"。要提就照实说：「当天复盘被引用 N 次」。
   - Reddit 板块不要把 AINews 标注的 `Activity` 写成"点赞数"或"评论数"（AINews 的 Activity 是综合活跃度分值）。照实写：「AINews 活跃度 N」。
4. **素材日期必须交代。** 如果 context 里出现「⚠️ 窗口内没有新一期…距今 N 天」，
   开头就要写明这批讨论发生在哪天，**绝对不能写成"今天"**。
5. **分歧要保留。** AINews 的 recap 里有 `Supportive / Neutral / Critical` 三档，Reddit 段落也常列出 `Commenters focused on... / criticized...`，只写一边等于骗人。每条重要话题都尽量给出"有人说 A、也有人说 B"。

## 结构

请严格按以下格式输出（各区块、段落与链接行之间必须空一行隔开，严禁挤在同一行）：

```
<b>🔥 X & Reddit 社区热议 · {日期}</b>

{一句话概括过去 48 小时 X 与 Reddit 上最核心的争论主线}

<b>1. {X 话题标题}</b>

{2-4 句：发生了什么、关键实测或数据}

{分歧：谁支持、谁质疑，各一句，点名人物/机构随文挂链接}

原帖：<a href="{x.com 直链}">@{handle}</a>（当天复盘被引用 {N} 次）

<b>2. …</b>

…

<b>🗣️ Reddit 实测与吐槽</b>

<b>[r/{Subreddit}] {Reddit 增量话题标题}</b>

{2-4 句：原帖核心发布/实测数据 + 评论区最尖锐的质疑、翻车反馈或工程共识}

原帖：<a href="{reddit.com 直链}">r/{Subreddit} 原帖</a>（AINews 活跃度 {N}）

<b>📎 主流媒体同期在报</b>

{Techmeme 里与上面话题对得上的 2-3 条，一行一条，带链接。对不上就整块省略}

<b>素材</b>：AINews {期次日期}（<a href="{issue url}">原文</a>）· 扫 544 个 X 账号 + 12 个 Subreddit
```

- X 话题控制在 **1–4 条**，Reddit 板块控制在 **1–2 条**（无独立增量或无 Reddit 素材时整块省略 `🗣️ Reddit 实测与吐槽`），宁少勿滥。
- 只用 `<b>` 和 `<a href>` 两种标签，别的一律不要（`send` 会做白名单清洗）。
- 篇幅目标 1200–2500 字（控制在单条飞书卡片 20KB 以内，不触发截断分页）。

## 语气

写给一个已经很懂 AI 的人看。不要科普基础概念，不要"随着人工智能的飞速发展"这类开场，
不要感叹号堆砌。**具体名字、具体数字、具体分歧**，其余都砍掉。

严禁 AI 腔旁白（禁止「值得注意的是」「原因并不复杂」「这标志着」「给出了一个反直觉的判断」等）；把判断直接归给具体发帖人、评测方或社区评论者，用事实和数字说话。

## 素材里的标记

| 标记 | 含义 |
|---|---|
| `=== FETCH_OK ===` | 取材成功，往下读 |
| `=== NO_TOPICS ===` | 窗口内没素材，**今天不写稿**，直接告诉用户 |
| `=== SKIP_ALREADY_RAN ===` | 今天已经播过了，停手 |
| `=== SKIP_PROXY ===` | 代理没开，停手并提醒用户 |
| `=== SOURCE_ALERT ===` | 某个 provider 连续零产，**在稿子末尾用一行告诉用户哪个源该查了** |
| `（已播过，勿作为新料）` | 这条 X 或 Reddit 原帖前几天播过了，可以作为背景引用，但别当今天的新料 |
